## 1. 项目与环境总览

### 1.1 项目目标

`职途洞察` 是一个大数据实践项目，目标是在四周实践周期内完成招聘数据的采集、清洗、存储、分析和可视化展示。典型流程如下：

```text
智联招聘数据
  -> Python 爬虫采集
  -> Pandas / NumPy 清洗
  -> MySQL 业务库存储
  -> HDFS 分布式文件存储
  -> Hive 数仓建表与 SQL 分析
  -> Spark 分布式计算
  -> ECharts / pyecharts / Flask 可视化
```

### 1.2 推荐运行路线

当前推荐路线：

```text
Windows 10/11
  -> Docker Desktop
  -> WSL2
  -> Docker Compose
  -> MySQL / Redis / Hadoop / Hive / Spark / Python 工具容器
```

推荐原因：

- 避免 Hadoop、Hive、Spark 在原生 Windows 上的脚本和兼容性问题。
- Java、Hadoop、Hive、Spark 的版本固定在容器中，环境更容易复现。
- MySQL、Redis、HDFS、Spark 等持久化数据统一放在 D 盘，便于控制磁盘占用。
- Python 工具容器已经包含项目依赖，不必在 Windows 本机反复补包。

原生 Windows 路线仍可作为备用方案，详见第 9 节。

## 3. Docker 环境安装与首次准备

### 3.1 前置条件

需要：

- Windows 10/11 64 位
- Docker Desktop
- WSL2
- 可用内存建议 14GB 以上，Docker 分配 8GB 左右

建议 Docker Desktop 资源：

```text
Memory: 8GB
CPU: 4
Swap: 4GB
Disk image / data location: D:\docker
```

如果 Docker Desktop 设置界面有磁盘镜像位置选项，优先改到 `D:\docker`。如果界面没有该选项，至少保证 Compose 业务数据在 `D:\docker\bigdata\data`。

### 3.2 Docker Desktop 安装器与校验

已准备的安装器：

```text
D:\docker\installers\Docker Desktop Installer.exe
```

版本：

```text
Docker Desktop 4.77.0.228796
```

SHA256：

```text
5B866599F0DE9208F4594D64AA33658FA55CBDD64E0DB13648CFFE12C91795D2
```

签名状态：

```text
Valid
Signer: Docker Inc
```

验证命令：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "D:\docker\installers\Docker Desktop Installer.exe"
Get-AuthenticodeSignature -LiteralPath "D:\docker\installers\Docker Desktop Installer.exe" | Format-List Status,SignerCertificate
```

说明：

- Docker 官方下载地址可能已经更新到新版本，而 winget 清单仍停留在旧版本。
- SHA256 与 winget 不一致时，不要只看 winget。至少要确认 Authenticode 签名状态为 `Valid`，签名方为 `Docker Inc`。

## 5. 代码位置与运行原则

### 5.1 推荐代码目录

```text
D:\bigdatashixun\project\src\python
D:\bigdatashixun\project\src\spark
D:\bigdatashixun\project\src\sql
```

Python 容器把项目根目录挂载为 `/workspace`，所以容器内路径是：

```text
/workspace/src/python
/workspace/src/spark
/workspace/src/sql
```

示例：

```text
D:\bigdatashixun\project\src\python\check_bigdata_connections.py
D:\bigdatashixun\project\src\python\mysql_spark_end_to_end_demo.py
D:\bigdatashixun\project\src\spark\your_spark_job.py
D:\bigdatashixun\project\src\sql\your_query.sql
```

### 5.2 容器内外地址区别

Windows 宿主机访问服务时：

```text
MySQL: 127.0.0.1:13306
Redis: 127.0.0.1:16379
HDFS UI: http://localhost:9870
YARN UI: http://localhost:8088
Spark UI: http://localhost:18080
HiveServer2: jdbc:hive2://localhost:10000
```

Docker 容器内部访问服务时：

```text
MySQL: mysql:3306
Redis: redis:6379
HDFS: hdfs://namenode:9000
WebHDFS: http://namenode:9870/webhdfs/v1
Hive Metastore: thrift://hive-metastore:9083
HiveServer2: jdbc:hive2://hiveserver2:10000
Spark Master: spark://spark-master:7077
```

### 5.3 Python 运行原则

优先使用 Python 工具容器：

```powershell
docker compose exec -T python python src/python/check_bigdata_connections.py
```

不优先使用 Windows 本机 Python：

```powershell
python .\src\python\check_bigdata_connections.py
```

原因：

- Windows 本机可能缺少 `pymysql`、`redis`、`requests`、`pyspark` 等包。
- Windows 本机不能稳定使用 Compose 服务名 `mysql`、`redis`、`namenode`。
- Python 工具容器已经放好项目依赖，网络和服务发现更稳定。

### 7.3 Python 通过 WebHDFS 访问 HDFS

当前 Python 容器没有额外安装 HDFS 客户端库，推荐直接使用 WebHDFS HTTP API。

保存为 `src/python/demo_hdfs_webhdfs.py`：

```python
import requests


BASE_URL = "http://namenode:9870/webhdfs/v1"
USER = "root"


def webhdfs_url(path: str) -> str:
    if not path.startswith("/"):
        path = "/" + path
    return BASE_URL + path


def list_status(path: str) -> None:
    response = requests.get(
        webhdfs_url(path),
        params={"op": "LISTSTATUS", "user.name": USER},
        timeout=10,
    )
    response.raise_for_status()
    items = response.json()["FileStatuses"]["FileStatus"]
    print("LIST", path)
    for item in items:
        print(item["type"], item["pathSuffix"], item.get("length", 0))


def mkdirs(path: str) -> None:
    response = requests.put(
        webhdfs_url(path),
        params={"op": "MKDIRS", "user.name": USER},
        timeout=10,
    )
    response.raise_for_status()
    print("MKDIRS", path, response.json())


def create_file(path: str, content: str) -> None:
    response = requests.put(
        webhdfs_url(path),
        params={"op": "CREATE", "overwrite": "true", "user.name": USER},
        allow_redirects=False,
        timeout=10,
    )
    response.raise_for_status()
    upload_url = response.headers["Location"]

    upload = requests.put(upload_url, data=content.encode("utf-8"), timeout=10)
    upload.raise_for_status()
    print("CREATE", path)


def read_file(path: str) -> str:
    response = requests.get(
        webhdfs_url(path),
        params={"op": "OPEN", "user.name": USER},
        timeout=10,
    )
    response.raise_for_status()
    return response.text


mkdirs("/user/root/python-demo")
create_file("/user/root/python-demo/hello.txt", "hello hdfs from python\n")
list_status("/user/root/python-demo")
print(read_file("/user/root/python-demo/hello.txt"))
```

## 10. 常见问题与处理

### 10.1 Docker Hub 报 `auth.docker.io/token EOF`

这是 Docker Hub 网络问题，通常不是 Compose 配置错误。

如果镜像已构建完成，直接启动：

```powershell
.\scripts\bigdata-docker.cmd up-all
```

如果缺镜像，稍后重试构建：

```powershell
.\scripts\bigdata-docker.cmd build
```

### 10.2 `apt-get 502 Bad Gateway`

多数是代理导致 Debian/Ubuntu 源访问异常。当前建议 `.env` 中保持：

```env
HTTP_PROXY=
HTTPS_PROXY=
```

如果直连失败，再恢复：

```env
HTTP_PROXY=http://host.docker.internal:7897
HTTPS_PROXY=http://host.docker.internal:7897
```

改完后重新构建：

```powershell
.\scripts\bigdata-docker.cmd build
```

### 10.3 Windows 本机 Python 缺包

例如：

```text
ModuleNotFoundError: No module named 'pymysql'
```

优先使用容器：

```powershell
docker compose exec -T python python src/python/check_bigdata_connections.py
```

不要优先在 Windows 本机补包，除非确实要在本机运行脚本。

### 10.4 Redis `HELLO 3` 报错

当前 Redis 是 5.0.14，使用 RESP2。Python 代码中应固定：

```python
redis.Redis(..., protocol=2)
```

### 10.5 HiveServer2 启动或权限问题

当前 Hive 配置保留：

```xml
<name>hive.metastore.event.db.notification.api.auth</name>
<value>false</value>

<name>hive.server2.enable.doAs</name>
<value>false</value>
```

这些配置用于避免本地实训环境中的 Metastore 事件权限和用户代理权限问题，不要随意删除。

### 10.6 Java 版本问题

Docker 大数据容器内使用 Java 8：

```text
Hadoop: Java 8
Hive:   Java 8
Spark:  Java 8
```

Windows 本机可以是 Java 21，不影响容器内运行。如果课程或依赖要求 Java 11，需要修改 Dockerfile 并重建镜像：

```powershell
.\scripts\bigdata-docker.cmd build
```

不要只改 Windows 本机 Java 版本来期待容器内 Java 变化。

### 10.7 Docker 数据看起来仍在 C 盘

Docker Desktop 本体、配置文件、锁文件可能仍在 C 盘，这是正常的。重点检查 WSL 数据目录是否为 Junction：

```powershell
Get-Item "$env:LOCALAPPDATA\Docker\wsl" | Format-List FullName,Attributes,Target,LinkType
```

期望：

```text
LinkType : Junction
Target   : D:\docker\desktop-wsl
```

业务数据检查：

```powershell
Get-ChildItem D:\docker\bigdata\data
```

### 10.8 中文显示异常

MySQL 中：

```sql
SET NAMES utf8mb4;
```

PowerShell 中：

```powershell
chcp 65001
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
```

连接 MySQL 时带上：

```bash
--default-character-set=utf8mb4
```

### 10.9 Hive SELECT 快但 GROUP BY 慢

`SELECT *` 可以直接读取 HDFS 文件。`GROUP BY` 会启动 MapReduce，所以慢很多。第一次运行尤其明显。

### 10.10 `yarn logs` 找不到日志

当前环境没有开启 YARN 日志聚合，所以 `yarn logs` 找不到日志是正常现象。可查看 ResourceManager 或 NodeManager 容器日志：

```powershell
docker compose logs resourcemanager
docker compose logs nodemanager
```

### 10.11 Spark 一直等待资源

如果看到：

```text
Initial job has not accepted any resources
```

处理：

```powershell
docker compose restart spark-master spark-worker
```

也要检查是否有旧的 `pyspark` 或 `spark-sql` 会话占用资源。

### 10.12 原生 Windows Hadoop 重复格式化后 DataNode 启动失败

通常是 NameNode/DataNode 的 clusterID 不一致。处理：

1. 停止 Hadoop。
2. 删除 `D:\bigdata\data\hadoop\namenode`、`datanode`、`tmp` 中的数据。
3. 重新执行一次：

```cmd
hdfs namenode -format
```

4. 再启动：

```cmd
start-dfs.cmd
start-yarn.cmd
```

### 10.13 原生 Windows `JAVA_HOME is incorrectly set`

检查：

- `hadoop-env.cmd` 里的 `set JAVA_HOME=` 是否正确。
- JDK 路径是否无空格。
- 如果必须在 `C:\Program Files\Java`，可尝试短路径，例如 `C:\PROGRA~1\Java\jdk1.8.0_xxx`。

### 10.14 原生 Windows 找不到 `winutils.exe`

检查：

- `winutils.exe` 和 `hadoop.dll` 是否放入 `%HADOOP_HOME%\bin`。
- `hadoop.dll` 是否复制到 `C:\Windows\System32`。
- 版本是否对应 Hadoop 3.3.6。
- 是否被杀毒软件或 Windows Defender 删除。

### 10.15 Hive 初始化字符集或外键错误

确保 MySQL 中 `hive_metastore` 字符集为 `latin1`：

```sql
ALTER DATABASE hive_metastore CHARACTER SET latin1;
```

### 10.16 MySQL 8 JDBC 报 `Public Key Retrieval is not allowed`

JDBC URL 中加入：

```text
allowPublicKeyRetrieval=true&useSSL=false
```

XML 中的 `&` 必须写成 `&amp;`。

### 10.17 端口被占用

检查端口：

```cmd
netstat -ano | findstr 端口号
```

结束进程：

```cmd
taskkill /PID 进程号 /F
```

也可以修改对应组件端口配置。Docker 环境中 MySQL 和 Redis 已避开本机默认端口，分别映射为 `13306` 和 `16379`。

## 12. 总结

当前项目的最佳实践是：

- Docker 路线作为主线，原生 Windows 路线作为备用。
- 代码写在项目目录，数据由容器持久化到 `D:\docker\bigdata\data`。
- 宿主机访问使用 `127.0.0.1 + 映射端口`，容器内部访问使用 Compose 服务名。
- Python 优先在 `zhitu-python` 容器运行。
- Hive 交互优先用 Beeline。
- Spark 访问 Hive 优先使用 Spark SQL 或 PySpark 的 Hive 支持。
- 每次验收以 `status`、Python 总检查脚本和 Spark SQL 为准。

最小可用验收命令：

```powershell
cd D:\bigdatashixun\project
.\scripts\bigdata-docker.cmd status
docker compose exec -T python python src/python/check_bigdata_connections.py
docker compose exec -T python python src/python/check_bigdata_connections.py --spark-job
docker compose exec -T spark-master spark-sql --master spark://spark-master:7077 -e "show databases;"
```
